# AFTER FOUR Backend

API-only Rails modular-monolith backend for AFTER FOUR. It includes the Milestone 1 infrastructure, the Implementation Phase 1 internal Order/Payment safety command foundation, the A1 Organization reference foundation, and the empty Package B Catalog integrity foundation. Authentication, public business mutation endpoints, and frontend integration remain deferred.

## Runtime baseline

- Ruby 3.4.12
- Bundler 2.6.9
- Rails 8.1.4.1
- PostgreSQL 18.x (development Compose file pins 18.7)

Use the exact Ruby version in `.ruby-version`. The lockfile is authoritative for gem versions.

## Reproducible Docker workflow

From `backend/`:

```bash
docker compose build backend
docker compose up -d database
docker compose run --rm backend bin/rails db:prepare
docker compose up backend
```

The development image pins Ruby 3.4.12 and installs the PostgreSQL 18 client so `structure.sql` is generated by a matching major. In another terminal, verify:

```bash
curl --fail-with-body http://127.0.0.1:3000/health/live
curl --fail-with-body http://127.0.0.1:3000/health/ready
```

Stop the services without deleting the database volume:

```bash
docker compose down
```

## Host Ruby workflow

Install exact Ruby 3.4.12 and PostgreSQL 18 client tools first, then run:

```bash
gem install bundler -v 2.6.9
bundle _2.6.9_ install
```

Native source builds require a compiler and PostgreSQL client headers. Supported Bundler platform packages avoid some local compilation but do not replace PostgreSQL 18 server testing.

## Start PostgreSQL 18

The Compose file is development-only and does not define a production deployment:

```bash
docker compose up -d database
docker compose ps
```

Defaults are safe local-development values:

```text
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=55432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DATABASE=after_four_development
POSTGRES_TEST_DATABASE=after_four_test
```

Override them with environment variables. Production uses `DATABASE_URL`; never use the development password outside local development.

## Prepare and load the database

For host Ruby, remove the `docker compose run --rm backend` prefix from these commands:

```bash
docker compose run --rm backend bin/rails db:prepare
docker compose run --rm backend bin/rails db:schema:dump
docker compose run --rm backend bin/rails db:schema:load
```

`config.active_record.schema_format = :sql`, so the reviewable dump is `db/structure.sql`. Application-owned tables cover the Phase 1 Order/Payment safety foundation, the A1 Organization references, and the empty Package B Category/Product/Variant integrity schema. Identity, refund, inventory, pricing, availability, menu data, and KDS tables remain excluded.

To reset only the development database, stop the backend and workers, verify `RAILS_ENV` is not `production`, then run:

```bash
docker compose run --rm -e RAILS_ENV=development backend bin/setup --reset --skip-server
```

This destroys and recreates `after_four_development`; it does not target the test or production database.

## Start the backend and worker

```bash
docker compose up backend
```

In another terminal, when queued jobs need processing:

```bash
docker compose run --rm backend bin/jobs
```

Solid Queue runs the pending-payment expiration scan. Phase 1 persists preparation-dispatch outbox events but intentionally has no delivery consumer or business preparation job yet. See [the transactional outbox boundary](docs/transactional-outbox.md).

The payment window defaults to five minutes (`300` seconds). `ORDER_PAYMENT_WINDOW_SECONDS` is read once while each Rails process boots. An explicit value must be a base-10 positive integer whose resulting boot-time deadline fits PostgreSQL `timestamptz`; zero, negative, blank, decimal, non-numeric, and unrepresentable values fail boot instead of falling back to the default. Keep one value across web and job processes.

## Checks

```bash
docker compose run --rm backend bundle exec rspec
docker compose run --rm backend bin/rubocop
docker compose run --rm backend bin/brakeman --quiet --no-pager --exit-on-warn --exit-on-error
docker compose run --rm backend bin/bundler-audit check --update

```

`bundler-audit --update` requires network access to refresh the advisory database.
See [the backend testing standards](../docs/development/after_four_testing_standards.md) for running individual specs, test organization, factories, isolation, and coverage.

## Health endpoints

- `GET /health/live` proves the Rails process can serve a request and does not query PostgreSQL.
- `GET /health/ready` runs a minimal PostgreSQL query and returns `503` with only `status` and `request_id` when unavailable.

Both return the correlation identifier in `X-Request-ID` and the JSON body. They never return hostnames, credentials, SQL, or exception details.

## Data conventions

- Application-owned primary keys default to PostgreSQL `uuid`; framework-owned Solid Queue tables retain upstream key types.
- Application-owned instants use `timestamptz`, and Rails reads/writes them in UTC; Branch-local display will use an IANA timezone. Framework-owned Solid Queue tables retain their upstream timestamp definitions.
- Future money columns use integer stored units plus `char(3)` currency; floating point is forbidden.
- Future quantities use `numeric(18,6)` and rates use `numeric(18,8)` with explicit domain rounding.
- Migrations and `structure.sql` are the schema source; do not edit a live database manually.
