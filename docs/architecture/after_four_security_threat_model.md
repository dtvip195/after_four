# AFTER FOUR Identity Security Threat Model v1.0

**Status:** Proposed controls; security review required  
**Date:** 2026-11-14  
**Scope:** Identity, sessions, role/Branch authorization, and audit for the first-party internal application.  
**Related:** [Identity & Branch Authorization](after_four_identity_authorization.md) · [Decision Register](after_four_identity_decision_register.md) · [ADR-0006](adr/0006-authentication-session-topology.md)

## 1. System and trust boundaries

Assets are employee identity, credentials, sessions, role/Branch grants, sensitive operational data, and audit evidence. Trust boundaries are the browser/POS device, TLS/reverse proxy, Rails application, PostgreSQL, secret store, approved MFA/recovery channel, and authorized operators. The frontend and a client-supplied Branch/role are untrusted. Internal network location is not authentication.

This model prioritizes realistic cafe-chain risks: shared or unattended terminals, guessed short PINs, phishing, stale employment access, Branch Manager misuse or compromise, cross-Branch identifier probing, and audit suppression. It does not propose a SOC platform, behavioral biometrics, or a general policy engine.

## 2. Risk priorities

| Priority | Threat | Impact | Prevention | Detection | Required tests |
|---|---|---|---|---|---|
| Critical | Cross-Branch data access | Staff view or mutate another Branch's orders, staff, cash, inventory, or customer-linked records. | Organization/Branch-scoped queries; effective Role + Employee Branch Assignment intersection; persisted resource scope; default deny; Owner exception explicit. | Audit denied scope attempts; alert repeated cross-Branch probes. | Matrix tests for every protected endpoint; temporary/expired assignment; list/detail/mutation; guessed UUID; Owner exception. |
| Critical | Privilege escalation | Staff grants Branch Manager/Owner access or invokes a privileged command. | Fixed code-owned capabilities; no client role trust; Owner approval for every Role/Branch Assignment change; Branch Manager assigned-Branch scope; MFA and sensitive-action step-up; prohibit self-grant/approval and Owner-only security administration. | Audit before/after grants and denied capability checks; alert Owner grants. | Self-grant, self-approval, mass-assignment, stale-session-after-grant/revoke, unassigned Branch, payroll-policy/final-close denial, approval tests. |
| Critical | Inactive employee access | Former or suspended worker continues using a session/PIN. | Temporary automated authentication lock is distinct from Owner-controlled suspension/deactivation; offboarding revokes sessions/authenticators and ends assignments; every request checks current User status and effective grants; history is retained. | Alert access attempts after suspension/deactivation and incomplete offboarding. | Existing-session deactivation; scheduled/future grants; concurrent request; explicit Owner reactivation; no automatic return; history retention. |
| High | Stolen credentials | Attacker authenticates as employee, especially Owner/Branch Manager. | Long screened passwords, adaptive hashes, mandatory MFA for Owner and every Branch Manager, generic errors, rate limits, step-up for sensitive actions. | Login success/failure and appropriate new-device events; anomaly signals; User-visible sessions. | Enumeration resistance, rate limits, MFA/step-up, session visibility/revocation, password rehash, compromised-password rejection. |
| High | PIN guessing | A 6–8 digit PIN is brute-forced at a shared terminal or across routes/devices/sources. | Individual PIN, enrolled POS + Branch boundary, no four-digit PIN, adaptive digest, required distributed account/device/source limiter, progressive delay/temporary lock, alternate-route coverage, and exclusion from general Session creation, MFA, step-up, recovery, and privileged actions. | Failed-PIN counters and alerts; correlate device/account; audit unlock without secret material. | Exact threshold/backoff/lock release, distributed attempts, source/device rotation, account enumeration, limiter outage, Branch/device mismatch, no secret logging. |
| High | Session theft/fixation | Attacker reuses a cookie and acts as victim. | High-entropy opaque secret; one-way stored verifier; Secure/HttpOnly/host-only/SameSite cookie; TLS; rotation; idle/absolute expiry; no URL/local-storage tokens; immediate revocation. | New/suspicious device and client-change signals; session list; revoked-token use audit. | Fixation/rotation, copied old token, expiry, logout/all-session revocation, cookie attributes, sensitive response cache headers. |
| High | Compromised manager account | Attacker changes staff/Branch access or operational records in assigned scope. | MFA/step-up; least capability; explicit Branch intersection; Owner approval for privileged grants; no Regional/chain scope by label alone. | Alert assignment/grant changes and unusual multi-Branch activity; immutable before/after audit. | Branch Manager cannot expand own scope, act outside assignments, grant Owner, or bypass second approval. |
| High | Invitation-delegation abuse | Delegate creates fraudulent/stale invitations or turns temporary authority into standing privilege. | Delegation is separate from Role Assignment; only active Branch Managers; Staff-only and assigned-Branch scope; maximum 90 days; no onward delegation/self-renewal/assignment approval; Owner revocation invalidates unused invitations. | Audit grant/use/revocation and invitation invalidation; alert scope/expiry denials and unusual invitation volume. | Expiry, lost assignment, suspension/deactivation, revocation race, unused-invite invalidation, self/privileged invite denial. |
| High | Unauthorized Owner-level operation | A non-Owner or stolen Owner session performs chain-wide security actions. | Exact capability plus active Organization-scoped Owner grant; mandatory recent MFA; separate reviewed Owner recovery; reauthenticate. | Immediate high-severity audit/notification for Owner grant, recovery, MFA removal, and audit access. | Staff/Branch Manager denial, stale MFA, recovery/approval, revoked Owner grant, session rotation. |
| High | Audit log tampering | Actor erases or changes evidence of fraud/access changes. | Append-only Security, Account lifecycle, Authorization/assignment, Financial, HR/payroll, and Operational events; explicit reader authorization; actor cannot alter own evidence; controlled holds/exports/anonymization; protected backups. | Integrity/sequence checks, database audit/monitoring, missing-event reconciliation, reader/export access logs. | Update/delete permission denial, self-evidence denial, transaction rollback atomicity, class coverage, redaction, hold/export/anonymization, backup/restore evidence. |
| High | IDOR / UUID probing | Valid identifiers bypass collection or Branch checks. | UUID is not authorization; scope query before lookup; identical hidden/not-found response; ownership derived from persisted relations. | Correlate repeated hidden-resource requests without revealing target. | Same response shape/status for absent/out-of-scope IDs; nested resource mismatch; alternate endpoint and bulk/export tests. |
| Medium-High | CSRF | Another site causes an authenticated browser to mutate data. | Same-site deployment; Rails CSRF token and origin validation on every unsafe method; SameSite cookie; no state-changing GET; no broad credentialed CORS. | CSRF failures with safe origin classification; alert spikes. | Missing/invalid/replayed-context token, foreign Origin, all unsafe verbs, JSON requests, valid same-origin request. |
| Medium-High | Account/recovery enumeration | Attacker learns staff identifiers or account states. | Generic login/recovery response and timing; rate limits; no public staff search. | Enumeration-shaped traffic and limiter events. | Existing/unknown/suspended/locked identifiers have equivalent public contract and bounded timing. |
| Medium | Shared/unattended terminal misuse | One employee acts through another's open POS session. | Individual PIN, 2-minute POS idle lock, required individual reauthentication, explicit operator identity, session/device list; no shared credentials. | Action audit includes User/Employee/device/Branch; detect impossible concurrency. | Exact 2-minute lock boundary, reauthentication, operator switch, concurrent sessions, action actor attribution. |
| Medium | Denial of service through lockout | Attacker locks legitimate users by repeated failures. | Progressive delay; source/device and account signals; bounded temporary lock; authorized recovery; avoid indefinite attacker-triggered lock. | Lockout volume and targeted accounts. | Distributed/source rotation, legitimate recovery, limiter reset, no bypass via alternate endpoint. |

## 3. Abuse cases and invariants

- Changing a request's `branch_id`, nested path, query filter, body owner, or frontend state never expands scope.
- A Branch Manager label without an effective Branch-scoped Role Assignment and matching Employee Branch Assignment grants nothing.
- Invitation Delegation grants neither a Role Assignment nor a Branch Assignment and never permits assignment approval, onward delegation, or Owner recovery.
- A Shift or Device association never creates standing authorization.
- Deactivation/suspension wins over otherwise valid sessions and assignments.
- An authentication failure never reveals whether identifier, status, password, PIN, or MFA failed.
- A recovery administrator never sees or chooses the User's final password/PIN and cannot suppress the audit event.
- A raw credential, session/recovery secret, MFA material, cookie/header, or unrestricted request body never enters logs, errors, audit, analytics, or jobs.

## 4. Security event handling

Login/PIN/recovery failures are expected security events, not application exceptions. Record safe reason categories internally while returning generic public errors. High-severity events include Owner grant/revoke, privileged recovery, MFA removal, mass session revocation, repeated cross-Branch denial, audit access/export, and an attempt to alter audit rows.

An incident response must be able to: request/execute Owner-controlled suspension; revoke all sessions; revoke/reset authenticators; end or suspend grants; identify affected Branches and actions by request ID/session lookup reference; preserve audit evidence; notify the Owner/security contact; and restore access through the approved recovery path. Owner recovery uses at least two pre-established independent factors, offline material, two independent proofs, and dual control; a Branch Manager cannot perform it independently. Exact proof, custodian, notification, retention, escalation, and response details remain security/legal/operational review decisions.

## 5. Verification gate

Before production, execute request/policy tests across all roles and Branch combinations, browser CSRF/cookie tests in the deployed topology, rate-limit tests through the real proxy path, session concurrency/revocation tests, audit redaction/immutability tests, dependency/security scanning, and a focused manual review of recovery and Owner-level actions. A passing happy-path login test is not sufficient evidence.
